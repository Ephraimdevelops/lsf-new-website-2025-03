# Supabase and Legacy Systems

## Finding

Supabase is **repository-active but application-inactive**. The dependency, committed public environment variables, `supabase/config.toml`, SQL migrations and extensive guides exist. No active `createClient`, Supabase import, query, auth call or bucket call was found in `src` or `convex`. The GitHub tree contains additional migrations not present in the downloaded ZIP, proving this checkout is still not a faithful Git clone even though the application source is substantially complete.

## Required verification

An owner must inspect Supabase production: database tables/row counts/recent writes, Auth users, Storage buckets/objects/access logs, Edge Functions, webhooks, cron, API logs and RLS policies. Compare recent records with Convex. Export and checksum a backup before any change.

## Recommendation

Prefer **formal decommission** after verification because Convex is the selected shared application backend. If Supabase contains unique production data, perform a mapped, rehearsed migration into Convex or retain it temporarily as read-only migration source with an owner and sunset date. Do not retain duplicate identity, CMS or legal-case write paths.

- `dist` is ignored locally but present in the ZIP and contains contaminated public artifacts; build output should be generated by CI, not reviewed as source of truth.
