### 5 October account-scoped mobile draft recovery

The mobile intake provider now uses separate SecureStore keys for each signed-in identity and for anonymous drafting. Its state is keyed by identity, so account changes reset in-memory intake state. It wraps the account-sync guard, preserving the same account's draft while synchronization temporarily replaces the screen. Anonymous drafts are not silently adopted after login: the intake entry offers an explicit bilingual transfer action, warning if an existing account draft will be replaced. Transfer creates a fresh request identity, saves to the selected account first, then removes the anonymous copy; it does not submit a request. Write or cleanup failures reject the transfer and retain recoverable storage.

Stored drafts are validated for supported enum values, field types and size limits, and unexpected persisted attributes are excluded before restoration. The old shared `haki_yangu_intake_draft` key is neither restored nor deleted automatically: it contains no reliable owner information, so migration cannot safely attribute it to the current account. This is a recovery limitation for legacy drafts, not a claim that they were migrated.

Validation: five synthetic storage-policy and transfer tests pass via `npm run test:intake-drafts`; mobile TypeScript and Android/iOS/web JavaScript exports pass. Actual SecureStore on phones, logout/account-switch rehearsal, authentication return navigation and populated bilingual restore-screen acceptance remain open. No real-account or release-verification gate is closed by these checks.

### 5 October interrupted request/evidence retry

Shared backend attachment calls now acknowledge the same request/storage-file pair without creating another attachment or incrementing the version. Replayed metadata must match the original name, type, size and note, and ownership is checked before replay. A committed attachment can be acknowledged after submission, while new attachments remain blocked. Both clients use the backend-returned version; mobile and web retain completed upload identifiers in memory to reuse them when an attachment call must be retried. Saving an already-submitted request now recovers its original reference before checking mutable directory availability; new or draft requests retain that check. Withdrawn submissions are rejected. The website also retains success/reference if session-storage cleanup fails, instead of presenting a committed submission as a failure.
